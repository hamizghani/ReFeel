# V3 inputs and boundaries

## Inputs

This revision builds on the approved photographic V2 project, the supplied Familiar source/deployable archives, mobile and desktop Stitch exports, attached DESIGN GUIDELINE, and the user's approved V3 instructions. The previous deployed website was observed in the cloud browser during V2 review. That observation does not establish that V3 has been deployed.

## Approved scope

Preserve the working marketplace and pastel composition. Add one properly deforming garment model for the first Cloud listing and reuse it in blue as an explicitly illustrative familiar reference. Animate the guided actions, allow manual rotation and zoom, provide immediate Next, hold after six seconds, improve relative feel language and editable descriptions, and make selling obvious. Both buyer and seller walkthroughs share these controls. Other garments remain photographed. Desktop and phone layouts are supported. There is no backend.

## Boundaries

Cloth simulation is an actual numerical solver, but its material parameters are authored. It is not a calibrated reconstruction, real capture or proof of textile mechanics. The blue version is not a scan of the photographed blue blouse. Shape, give, texture and softness comparisons use attributed qualitative descriptions. Unknown values do not become known through watching an animation.

Twelve catalogue listings and one private blue template use 36 local photos. Prepared identities, size, measurements, composition descriptions, condition, profiles and commerce facts are illustrative. Existing imagery is not newly captured secondhand inventory. Missing reverse, label and wear views remain missing.

The six-step camera-style flow does not request device camera access, store real footage or upload files. Walkthrough completion records progress only. Payments, messages, delivery, moderation and account actions are local scenarios. Records belong to this browser profile; there is no synchronization.

## Verification

Release evidence documents checks actually run. Numerical stability does not establish real tactile prediction. Headless Chromium with software WebGL and simulated mobile sizes does not certify physical-phone frame rates, Safari/Firefox or full human accessibility conformance. A successful clean build does not mean the ZIP is live on Vercel.
