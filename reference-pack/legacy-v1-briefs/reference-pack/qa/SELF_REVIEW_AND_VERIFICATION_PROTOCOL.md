# Self-review and verification protocol

Apply this loop before delivery:

1. Define success from the request, constraints, intended audience, reference material, and standards.
2. Produce a complete first attempt.
3. Review it as a demanding evaluator. Use an independent critic if available and identify the critic accurately.
4. Privately score task fulfillment, correctness, completeness, clarity and usability, and presentation or execution quality from 0 to 10. A score below 8.5 requires revision.
5. Verify calculations, citations, code behavior, layout, responsiveness, asset manifests, 3D behavior, persistence, source preservation, and build output.
6. Rank issues by impact.
7. Fix critical errors and unmet explicit requirements first, then substantive weaknesses, then polish.
8. Recheck affected areas for regressions.
9. Repeat for up to four review and revision rounds.
10. Stop only when every applicable dimension reaches at least 8.5 and no critical requirement is unmet.

Keep ratings, critic dialogue, process commentary, and internal review notes outside audience-facing product files. Do not claim a check was performed unless its output was inspected. State material verification gaps plainly in the handoff notes.
